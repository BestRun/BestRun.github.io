对AI安全的一些思考

好久没冒泡了，简单解释一下我现在的状态。 在TUM交换快乐玩耍，下学期要去 CISPA 做毕设。 但是最近 CISPA 出了点状况（危），导致我不得不考虑重新审视一下未来。 与其说是对AI和安全的一些思考，不如说是对自己的一个深度探索。

最近在cispa做了一项 benchmark 的工作，（本来说是为博士的研究提前做数据集，现在看来也可能就只是一篇benchmark文章了）。

AI安全，最近非常热门的一个方向。无论是学术界还是工业届都有越来越多的人涌入。可能最近经常有各种新闻，claude的xxx模型，挖出了xxx个firefox漏洞，等等等等。所以，AI在安全上的能力到底发展成什么样子呢？我觉得我还是有资格可以讲一讲的。

但细分的话AI安全，可以分为两个方面: AI for security 和 AI security. AI security 本质上就是 AI 自己的安全，在学术界，早期就是各种测 prompt injection（早就被玩烂了），现在可能焦距到 agent 的 security 和如何做防护上。在工业界，大家关注的更多还是业务中 AI 服务的安全性（这里我没有太多发言权）。

更想说一说的是 AI for security, 我们从 AI 能够解一些数学题，在各种 reasoning benchmark 上得分越来越高，可以看出 AI 在 security 领域有着巨大的潜力。于是相应的安全方面的 benchmark 诞生了，UCB团队做了 cybergym, exploitgym 用于测试 agent 在安全领域的能力。但是模型和agent的能力越来越模糊，（跑偏了，不是来讲现有研究的limitation的）。

至少我觉得 AI for security 是有无限可能的，虽然有些朋友并不看好这块。那么在学术界还是工业界做成了我最近一直在思考的问题。学术界，计算资源会紧缺一些，但是胜在自由度高，你想研究的课题比较自由。工业界胜在资源丰富，但缺点是总要为业务服务，很难去做自己想做的的研究。

我觉得去工业界需要考虑以下几个维度： 入场时机 x 发展前景 x 自身

总入场时机的角度：现在无疑是最好的入场时机，LLM 的 reasoning 能力飞速提升（这学期选了一个reasoning相关的seminar，读了很多相关领域的论文，其实这块还有很大的提升空间），缺的是数据和垂直的训练方法。如果现在入场，无疑是很好的的一个时机，能在该领域积累经验。

发展前景：首先，“钱”景肯定是不错的，但是会不会有天花板的存在，这个还不好说。因为没有接受博士的训练，可能工程能力和科研能力无法balance。

自身的角度：这个我觉得是最重要的，那就是我究竟适合哪条道路。其实相比于长期无正反馈，我喜欢那种短期的刺激感。可能是因为，我是安全竞赛的走出来的半学院派，而非传统的科研人。所以我迟疑了，博士能带给我的，真的值得吗，如果这三年我花在业界，也许已经可以攒一部分名气。

不管了，下学期就边做毕设，边找业界的机会吧，如果cispa的风波过了，再观望一下。
